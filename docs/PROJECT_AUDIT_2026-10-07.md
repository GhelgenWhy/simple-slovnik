# Отчёт о проверке Slovník

Дата: 7 октября 2026 года. Проверенный HEAD: `76cd3cf`, ветка `main`.

## Вывод

Десктоп содержит два независимых словаря — чешский и английский. Мобильное приложение и имеющийся APK предоставляют только чешский словарь. Английский словарь на телефоне ещё не реализован; синхронизация английского отсутствует на обеих платформах. Это соответствует границам исходного английского плана, а не является случайно отключённой функцией.

APK существует, его архив и Android-подпись исправны. Однако его ядро старее текущих исходников. Кроме того, проверка выявила воспроизводимые ошибки мобильного добавления и синхронизации. До использования приложения как надёжного единственного места хранения слов рекомендую исправить эти ошибки и провести приёмку на телефоне.

Проверка включала `AGENTS.md`, `README.md`, `mobile/README.md`, `server/README.md`, `docs/MOBILE_PLAN.md`, `docs/ENGLISH_DICTIONARY_PLAN.md`, исходники, тесты, журнал сборки и содержимое APK. Код приложения не изменялся. Продакшен-сервер и пользовательские словари не изменялись; диагностические сценарии работали с временными БД. Повторная сборка APK не выполнялась.

## Как настраивается синхронизация

### Телефон

1. Подключить телефон через Tailscale к тому же tailnet, что и сервер.
2. Открыть экран **Sync**.
3. Ввести URL `https://ghelgenserver.taile8591e.ts.net:8443`.
4. Ввести значение серверного `SLOVNIK_TOKEN` без префикса `Bearer `. Сам токен находится на сервере в `/opt/slovnik-sync/.env`.
5. Нажать **Uložit nastavení**.
6. Нажать **Pull**, чтобы получить чешские слова, либо **Push**, чтобы отправить локальные изменения.

Настройки сохраняются в локальной SQLite, таблица `sync_state`: `config/server_url`, `config/token`. Там же находятся `device_id`, `last_sync_at`, `bootstrap_done`. Маскировка поля пароля не шифрует токен в БД. Если запускать Push/Pull без сохранения, используются текущие значения полей, но после перезапуска они не будут сохранены.

### Компьютер

На чешской вкладке открыть **🔗 Sync…**, указать тот же URL и токен. Настройки сохраняются через QSettings в `HKCU\Software\Slovnik\slovnik`, ключи `sync/server_url`, `sync/token`. Перед первым Pull с нового телефона изменения с ПК необходимо отправить Push. Изменения с телефона попадут на ПК после Push на телефоне и Pull на ПК.

### Семантика и ограничения

- Pull с кнопки защищает **неотправленные локальные правки** (`keep_dirty_local=True`). Для остальных записей применяется LWW.
- Push отправляет dirty-записи. Если сервер уже содержит более новую версию, она принимается локально (`accept_server_conflicts=True`), а проигравшая локальная правка архивируется. Если новее клиентская версия, она побеждает на сервере. Подпись «Push — выигрывает сервер» чрезмерно упрощает это поведение.
- LWW сравнивает `(updated_at, device_id)`. Dirty защищает от пропуска отправки при расхождении часов, но **сам выбор победителя по-прежнему зависит от часов устройств**.
- Удаления передаются tombstone-записями. Локальные id между устройствами не сопоставляются; идентичность — чешское слово.
- Сервер использует Bearer-токен, без токена возвращает 401; при отсутствии серверной настройки токена — 503, кроме `/health`.
- Всё выполняется вручную, фоновый поток используется только после нажатия кнопки. Английские записи не передаются.

Описанный продакшен в заметке — systemd + SQLite + Tailscale TLS. Его текущее сетевое состояние и фактическая версия кода удалённо не проверялись.

## Найденные ошибки и приоритеты

### P1 — кнопка «+» может перезаписать существующее слово

Источник: [обработчик кнопки](D:/projects/simple_slovnik/mobile/src/main.py:92), [сохранение](D:/projects/simple_slovnik/mobile/src/main.py:343).

Сценарий: открыть существующее слово → вернуться в список → нажать «+». Обработчик вызывает `_show_screen("edit")`, но не сбрасывает `edit_id`. В проверке обработчиков с минимальным объектом Page редактор сохранил id `1`; после ввода «new word» количество записей осталось `1`, а прежняя запись была переименована.

Исправление: кнопке добавления вызывать `_open_editor(None)`. Добавить проверку последовательности «редактирование → назад → новое слово». Исправление должно попасть в пересобранный APK.

### P1 — Push подтверждает также изменения, которых не было в запросе

Источник: [push](D:/projects/simple_slovnik/src/slovnik/sync.py:243), [clear_dirty](D:/projects/simple_slovnik/src/slovnik/db.py:445).

После ответа вызывается `clear_dirty()` для **всех** текущих dirty-записей. Пока сеть работает, пользователь может изменить или добавить запись. В воспроизведении правка во время запроса осталась локально, сервер получил прежний перевод `v1`, но локальный `dirty` стал `0`. Следующий Push её не отправит.

Исправление: подтверждать только снимок отправленных записей и только при совпадении версии. Лучше использовать монотонный номер локальной ревизии, а не полагаться только на время. Проверить редактирование, добавление и удаление во время запроса.

### P1 — переименование не удаляет старое слово на сервере

Источник: [update_word](D:/projects/simple_slovnik/src/slovnik/db.py:266), матчинг по `cs` в сервере.

Сценарий: отправить `cat` → изменить головку на `kitten` → Push. Сервер содержит две активные записи: `cat` и `kitten`. Другие устройства получат обе; последующий Pull может вернуть старую и на исходный клиент.

Исправление: для текущего протокола атомарно сохранять tombstone старого имени и новую запись. Альтернатива для следующей версии протокола — стабильный UUID записи и независимое изменяемое имя. Требуются проверки конфликтов с уже существующим новым именем и офлайн-переименования.

### P1 для больших словарей — Pull пропускает записи после лимита 10 000

Источник: [серверный лимит](D:/projects/simple_slovnik/server/app.py:46), [выборка](D:/projects/simple_slovnik/server/app.py:211), [сохранение курсора](D:/projects/simple_slovnik/src/slovnik/sync.py:183).

Сервер возвращает первые 10 000 строк, а клиент продвигает курсор до текущего серверного времени. В воспроизведении с 10 001 старой записью первый Pull получил 10 000, второй — 0. Одна запись осталась за курсором. Перекрытие в пять секунд не решает отсечение старого накопленного набора.

Исправление: страничная выдача с продолжением по устойчивому ключу, например серверному sequence id. Клиент должен дочитывать страницы; время ответа не должно обозначать завершение неполной выдачи. Проверить одинаковое received_at у записей на границе страницы.

### P2 — новый или восстановленный сервер не заполняется обычным Push

`bootstrap_done` и `last_sync_at` общие для БД, а не для конкретного сервера. После успешной синхронизации смена URL не сбрасывает их. В воспроизведении новый SyncClient с другим URL отправил `0` записей; сетевой запрос вообще не потребовался. При восстановлении пустой серверной БД по прежнему URL проблема такая же.

Утверждение заметки «первый Push с ПК возвращает все данные» верно лишь для клиента без завершённого bootstrap или при предварительной пометке записей dirty.

Исправление: добавить явное действие «Заполнить сервер всеми локальными словами», хранить состояние по серверу/языку и определять смену поколения серверной БД. При восстановлении согласовать поведение tombstones и конфликтов, а не просто незаметно сбрасывать состояние.

### P2 — мобильные smoke-тесты не работают и не входят в основной прогон

Источник: [путь SRC](D:/projects/simple_slovnik/mobile/tests/test_main.py:8).

Путь вычисляется как `mobile/mobile/src/main.py`, поэтому обе проверки падают с FileNotFoundError. Обычный `pytest tests/` не запускает `mobile/tests/`. После исправления пути также необходимо изолировать импорт мобильного пакета от установленного desktop-пакета; текущие smoke-тесты не проверяют UI-сценарии.

Исправление: поправить путь, добавить мобильные проверки в обязательный общий запуск и проверить основные обработчики. Добавить отдельную проверку состава выпускаемого APK.

## Дополнительные улучшения

1. **Английский на телефоне.** Параметризовать мобильный список, редактор, CRUD и проверку через уже существующий `lang`; добавить переключатель Czech/English и en_US assets. Сохранять независимость поиска и таблиц. Это отдельная задача от английской синхронизации.
2. **Английский sync.** Версионировать API, передавать язык и использовать раздельные серверные таблицы либо ключ `(language, identity)`. Разделить курсоры и bootstrap по языку. Предусмотреть совместимость старого чешского APK.
3. **Хранение БД на телефоне.** В `paths.py` выбирается первый доступный каталог в порядке cwd → temp → home, хотя docstring говорит cwd → home → temp. Риск потери/смены пути при очистке cache или обновлении требует проверки на устройстве. Использовать стабильный каталог постоянных данных приложения, предусмотреть миграцию старого файла и экспорт резервной копии.
4. **Конфликты.** Добавить просмотр обеих версий и восстановление локального архива. На сервере входящая проигравшая версия возвращается как конфликт, но сама не записывается в `conflicts`; сервер архивирует прежнюю версию, когда входящая побеждает. Документация обещает более широкое архивирование, чем реализовано.
5. **Надёжность ошибок.** Валидировать структуру ответов API и защищать мобильный sync-поток `try/finally`: неожиданный сбой SQLite/структуры ответа сейчас может оставить кнопки выключенными. Показывать отсутствие spellcheck-словаря: сейчас fallback на правила может завершиться сообщением «без ошибок» без указания неполной проверки.
6. **Большие списки.** Mobile загружает максимум 1000 слов/результатов без пагинации и пояснения ограничения; поиск пересоздаёт список на каждое изменение ввода. Добавить загрузку страниц, индикатор общего количества и небольшую задержку поиска.
7. **Выпуск APK.** Зафиксировать проверенные зависимости вместо одного `flet>=0.86.5`, сохранять lock/build manifest с commit и контрольными суммами, увеличивать versionCode. Завести постоянный release-keystore и сохранить его резервную копию. Переход с debug на другой ключ требует отдельного плана переноса данных. Для уменьшения размера рассмотреть выпуск по ABI после проверки на целевом телефоне.
8. **Соединения SQLite.** `_connect()` используется через `with conn`, что завершает транзакцию, но не гарантирует закрытие соединения. Использовать явное закрытие/контекстный менеджер. Во временной диагностике Windows встретилась блокировка файла при очистке; связи с конкретным соединением отдельно не исследовались.
9. **Токены и бэкапы.** При добавлении резервного копирования отделить словарные данные от credentials; рассмотреть системное защищённое хранилище. Бэкап сервера делать SQLite backup API или `.backup`, а не обычным копированием живого файла при WAL.
10. **Документация.** Исправить FAQ о неподключённом sync UI, обещание восстановления одним Push, границы серверного архива конфликтов и старые планы. `%f` SQLite даёт миллисекундную дробную часть, а не гарантированную микросекундную уникальность; для порядка нескольких быстрых правок нужен явный номер ревизии. В дереве отсутствует `.github` workflow, хотя mobile README упоминает CI.
