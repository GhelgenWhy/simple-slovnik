## Оставшиеся воспроизводимые ошибки

Все дополнительные сценарии выполнялись на временных локальных БД через FastAPI TestClient. Production-слова не изменялись. Результаты ниже относятся к коду, входящему в текущий APK и работающему на сервере.

### P1 — Pull может пропустить конкурентное изменение на последней странице

[server/app.py](D:/projects/simple_slovnik/server/app.py:420): после SELECT/fetchall сервер отдельно читает `max_seq` и, когда `has_more=False`, продвигает курсор до него. Выборка и чтение max_seq не защищены одним снимком транзакции.

Воспроизведение: сервер содержит `first` с seq 1. Между завершением fetchall и чтением max_seq другой запрос записывает `between-select-and-cursor` с seq 2. Первый Pull возвращает только `first`, но `next_cursor=2`. Следующий Pull с cursor 2 возвращает пустой список, хотя новое слово существует на сервере.

Исправление: не продвигать курсор за последнюю реально выданную seq; для пустой страницы оставить входной курсор. Если требуется продвижение по high-water mark, читать его и данные в одной согласованной транзакции/снимке. Нужен тест записи именно между fetchall и чтением метаданных, а не только между страницами.

### P1 — пустой успешный ответ Push снимает pending

[src/slovnik/sync.py](D:/projects/simple_slovnik/src/slovnik/sync.py:599): ответ `{}` принимается как отсутствие конфликтов; далее вызывается `clear_dirty_snapshot`, хотя подтверждения приёма записей нет.

Воспроизведение: создать pending-правку; вернуть `{}` на POST вместо серверного ответа. Получено `result.ok=True`, dirty стал 0. Отправленная версия может больше не попасть на сервер.

Исправление: до любых подтверждений проверить обязательные поля ответа, типы и количество результатов, конфликтные строки, identity/generation. Некорректный ответ должен оставлять снимок pending и возвращать ошибку. Аналогично проверить типы/монотонность cursor и `has_more` в Pull.

### P2 — требование полной выгрузки не сохраняется между попытками

[src/slovnik/sync.py](D:/projects/simple_slovnik/src/slovnik/sync.py:323): `_identity_check` сразу запоминает новую идентичность и сбрасывает состояние. Следующий Push уже видит «same» и может выполнить обычный bootstrap вместо обязательной явной полной выгрузки.

Воспроизведение: синхронизировать активное слово и tombstone с сервером A; переключиться на пустой B. Первый Push: `ok=False`, `needs_full_upload=True`. Повторный обычный Push: `ok=True`, `needs_full_upload=False`, отправлена одна активная запись; чистый tombstone не попал в bootstrap.

Исправление: сохранять флаг обязательной полной выгрузки отдельно по языкам до завершения explicit full upload; проверять повторные попытки и последовательность Pull → Push после смены сервера. Обе языковые таблицы должны проходить это независимо.

### P2 — full_upload меняет авторство

[src/slovnik/sync.py](D:/projects/simple_slovnik/src/slovnik/sync.py:438) помечает все записи dirty и затем вызывает обычный `_push`, который выполняет `stamp_device_id` для всех dirty-записей.

Воспроизведение: у записи `device_id=original-author`; клиент с device id `A` запускает full_upload. Автор записи после операции — `A`, а не `original-author`. Это меняет LWW tie-breaker при неизменном timestamp и противоречит обещанию сохранить авторство.

Исправление: отличать локально изменённые версии от записей, временно помеченных для полной выгрузки. При переносе сохранять прежний авторский ключ, а новый device id ставить только на реальные локальные правки. Проверять авторство и timestamp активных записей и tombstones.

## Исправления, внесённые при проверке

В `.github/workflows/ci.yml` исправлены две несогласованности:

1. Mobile job устанавливает исходный пакет через `pip install --no-deps -e .`. Ранее устанавливались только Flet и pytest, но `tests/conftest.py` импортирует `slovnik.spellcheck`; на чистом runner пакет был недоступен. Установка без зависимостей сохраняет этот job без Qt.
2. APK job использует Python 3.14 вместо 3.12. Проверка распаковывает Python 3.14 bytecode через marshal и сравнивает с компиляцией исходников; выполнять её на Python 3.12 некорректно. Обновление Python внутри упаковщика в будущем требует согласованного обновления проверяющего runtime.

Общий код, APK и production `app.py` при этой проверке не менялись. Поэтому соответствие APK исходникам и совпадение серверного кода сохраняются. Четыре дополнительные ошибки документированы для следующего исправления; текущий коммит сохраняет реализацию и результаты проверки, а не объявляет релиз полностью принятым.

Manifest APK корректно записывает старый HEAD `76cd3cf` и `git_dirty=true`: сборка выполнена до коммита изменений. Это не доказательство сборки из чистого коммита. После исправления оставшихся ошибок нужен новый APK/manifest с новой версией и повторная проверка сервера.
