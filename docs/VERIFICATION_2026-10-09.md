# Итоговая проверка плана и релиза

Первичная проверка: 9 октября 2026 года. Дополнение по телефонному QA
Push/Pull: 11 октября 2026 года. Проверены исправления sync, APK 0.2.2,
защищённое хранение токенов, развёрнутый сервер и телефон Redmi Note 14
Pro 5G. Проверка выявила четыре дефекта; они исправлены в коммите
`459bd9b` (`fix: close remaining sync integrity gaps`).

## Исправления и регрессии

- v2 Pull продвигает курсор только до последней фактически выданной строки.
  Push подтверждает только снимок отправленных ревизий; пустой или
  некорректный ответ не снимает `dirty`.
- Требование полного upload сохраняется после повторного обычного Push.
  Полный upload сохраняет авторство существующих строк.
- Для случаев добавления/изменения во время запроса, cursor race, пустого
  ответа, повторного Push и сохранения авторства добавлены регрессионные
  сценарии. Ядро синхронизации обновлено и в `mobile/src`.
- Полный запуск из корня репозитория: `.venv/Scripts/python.exe -m pytest
  -q` — **374 passed**, 2 предупреждения зависимостей. `pytest` включает
  `mobile/tests`.

## Защищённое хранение токена

- Desktop сохраняет токен в Windows Credential Manager через keyring;
  URL остаётся в QSettings. Старый `sync/token` удалён только после
  успешного secure-store write/read-back. На этой машине миграция прошла,
  legacy setting пуст, длина токена 64 символа; значение токена не
  выводилось в лог.
- Mobile использует Android Keystore через `flet-secure-storage==0.86.5`.
  Legacy `config/token` мигрируется при первом открытии экрана Sync только
  после подтверждённого чтения; при ошибке исходное значение сохраняется.
  После миграции повторная TLS-проверка телефона прошла: сервер вернул
  protocol 2, 95 Czech слов.
- Добавлены 7 тестов миграции, read-back и отказа защищённого хранилища;
  они входят в общий набор из 374 тестов.

## Телефонный Push/Pull на изолированном сервере — 11 октября

- Включена настройка Xiaomi **Developer options → Install via USB**;
  установку одноразовой сборки подтвердил системный экран Android.
  Отдельный пакет `cz.slovnik.slovnik_qa` (0.2.2, versionCode 4)
  установлен рядом с официальным приложением, не поверх него.
- Tailscale на телефоне был отключён. После подключения к той же tailnet
  MagicDNS разрешил имя тестового ПК, и проверка приложения подтвердила
  тестовый сервер по TLS: protocol 2.
- На отдельной пустой БД проверен полный обмен обоих словарей:
  телефон отправил по одной новой записи `cs` и `en`; затем получил по
  одной отдельной записи каждого языка, заранее записанной на сервере.
  Списки на телефоне показали по 2 из 2 слов; курсоры `cs=2`, `en=2`,
  ожидающих Push-изменений — 0. `/sync/info` независимым запросом подтвердил
  `cs=2`, `en=2`; production-БД не использовалась и не менялась.
- После проверки QA-пакет удалён, временный listener на порту 8111
  остановлен, Tailscale Serve на ПК очищен (`No serve config`). Официальный
  пакет `cz.slovnik.slovnik_mobile` 0.2.2 остался установлен.

## Граница проверки и отдельные задачи

Кнопка Push на телефоне не отправляла тестовую правку в production: это
создало бы постоянное изменение или tombstone в личном словаре. Реальный
телефонный Push/Pull обоих языков прошёл на отдельном тестовом сервере;
двунаправленное слияние, tombstones, конфликты, повтор запроса и потеря
ответа дополнительно покрыты регрессионным набором и изолированной
приёмкой сервера.

Перенос токена завершён. Смена общего debug-сертификата на сохранённый
release-keystore остаётся отдельной задачей управления выпуском: новый
сертификат запретит обновление установленной версии поверх и требует
контролируемого резервирования и восстановления данных. Остальные
обязательные этапы плана и развёртывания завершены.
